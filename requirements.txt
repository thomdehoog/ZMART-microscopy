# What the ZMART viewer and its writer need in order to run.
#
# This is a short list on purpose. The viewer's job is to show images that are
# already on disk, and the heavy work -- decoding, drawing, deciding what to fetch
# next -- happens in the browser rather than in Python. The server here reads small
# description files, measures how bright an image is from the smallest copy of it,
# and serves bytes. That needs very little.
#
# Install into a Python 3.10-3.12 environment:
#
#     python -m pip install -e .
#
# The tools for running the tests are a separate list, because somebody who only
# wants to look at their data does not need them:
#
#     python -m pip install -e ".[dev]"

# Reads and writes the OME-Zarr images themselves. Version 3 is required rather
# than merely preferred, because the writer depends on behaviour that moved within
# version 3: whether a chunk holding nothing is written at all, what the default
# compressors are, and what resizing an array gives back. An older zarr would not
# be slower, it would be wrong in ways that are hard to see -- and the first of
# those is read directly by the code that works out how far a timelapse has got.
zarr>=3,<4

# Arithmetic on image data: measuring how bright an acquisition is, so that it can
# be shown sensibly the moment it opens, and building the shrunk-down copies the
# viewer draws when zoomed out.
numpy>=1.24

# Shows the viewer in its own desktop window instead of a browser tab. Optional:
# without it the page still serves and can be opened in any browser, and the
# launcher says so plainly rather than failing. On Windows the window is drawn by
# WebView2, which is Chromium underneath, so the drawing engine behaves there as
# it does in Edge.
pywebview>=5
