# Review: per-commit bake for live governed pictures + writer campaign

## (1) Verdicts, Q1–Q7

**Q1 (gate) — hole found.** The chosen shape (synchronous patch inside the derive; governed stores consult the run before any file door, backend included) is right, but three doors past the run remain: `served.a_manifest_governs` fails **open** when classification fails (defect 3), the backend's `_a_piece_of_a_governed_picture` parse is bypassable by path aliasing (defect 4), and re-declaration under a running server leaves a stale cached classification (defect 5). Additionally the synchronous patch is silently skipped in the rollback and declare-race scenarios (defects 1, 2), so "files are always current once anyone can know" does not actually hold in those cases.

**Q2 (edges) — sound.** Verified statically: interior pieces need no padding (source is exactly 2×wanted); only global-edge pieces pad, and `mode="edge"` there replicates the array's true last row/column, identical to whole-array padding. The piece-index halving `(row//2, column//2)` in `_keep_the_bake_true` maps correctly for any picture size, because `ceil(ceil(H/2)/P) = ceil(ceil(H/P)/2)` (so the halved max index always lands on the upper grid's last piece). The staging array copies the level's own `zarr.json`, so encoding cannot drift; dtype/mean/round chain matches `_bake_the_coarse_ground`; reading absent lower chunks as fill matches what the fresh bake reads back from its own files.

**Q3 (concurrency) — sound intra-process, hole inter-process.** `_bake_guard` + forward-only stamp is correct for racing threads of one `GovernedRun`. But the guard is per-instance: `declare --bake` against a store a server is serving, or two servers on one store, share the `.baking` sidecar names and the `.patching-{level}` staging directory (`shutil.rmtree` under the other's feet, `os.replace` of a file the other holds) with no file-level lock. And "forward-only" is the wrong monotone under rollback (defect 1).

**Q4 (swap inheritance) — not implemented, not decided.** No swap-inheritance mechanism (hard link, copy, or fallback chain) exists anywhere in `viz_studio`; the only hits for it are the review prompt's own text. The addendum's "the plan above was implemented" is false for §3's generation-swap clause.

**Q5 (crash honesty) — hole found.** The stamp (`baked.json` event count) is the bake epoch and works for crashes in a forward-moving history: catch-up costs the missed changes, a torn stamp reads as −1 and honestly (expensively) dirties everything. It is **not** honest under rollback (defect 1) or geometry change (defect 6), and it is coarser than a durable dirty-set: it names missed *positions*, resolved to their **current** footprints only — exactly where defect 6 leaks.

**Q6 (per-change validation) — sound, with named invalidation obligations.** See §3 below.

**Q7 (shared routing) — yes, with refusal kept separate.** See §3 below.

## (2) Ranked defects

**D1 — The stamp count is not rollback-safe; a whole-history rollback leaves withdrawn ground served from baked files. HIGH, high confidence.**
`governed.py`: `_keep_the_bake_true`, `_the_stamped_events`, `_the_ground_the_bake_missed`. The stamp is a bare event *count* compared with `>=`. A rollback — history truncated (the gateway's own `len(events) < self._folded` reset path proves this is supported) or `committed.json` revision lowered (which shrinks `manifest.events()` via its ceiling) — makes `len(events)` drop below the stamp. Mid-session: the derive computes a correct `dirtied` (both-snapshot footprints), but `_keep_the_bake_true`'s first line, `if self._the_stamped_events() >= folded: return`, skips the patch. Cross-session: `_the_ground_the_bake_missed` returns `None` ("current") for `absorbed >= len(events)`. Either way the rolled-back position's baked files survive, and `served.the_bytes_behind` then answers them via `baked.is_file()` — a fail-closed withhold violated in exactly the operation requirement #2 names. Cure: stamp identity, not just count (e.g. count + last event revision/hash, or the manifest fingerprint at fold time); treat stamp-ahead-of-history as "coverage unknown → everything dirty"; never compare with plain `>=`.

**D2 — `declare_a_governed_picture(bake=True)` on a live run stamps events it never baked; the missed commits are never patched. HIGH, high confidence.**
`declare.py` line 206: `governed.stamp_the_bake(store)` with `events=None` reads `len(manifest.events())` *at stamp time* (`governed.py stamp_the_bake`), but the files hold the state of the `governed.composer()` snapshot taken before `_bake_the_coarse_ground` ran — seconds to minutes at scale. Any commit landing in that window is claimed absorbed but never baked. The serving path then skips patching it forever: the next commit's derive patches only its own footprint and advances the stamp past the missed ones. If a missed commit was a replacement, the superseded generation is served from files indefinitely. Cure: capture the folded count at compose time (the serving path already does exactly this — `self._run._folded`) and pass it as `events=`.

**D3 — Classification failure fails open: baked files served statically past the manifest. HIGH consequence, medium likelihood, high confidence in mechanism.**
`served.py`: `a_manifest_governs` returns `False` whenever `_composer_for` returns `None`, and `server.py _serve_from_data` then takes the plain `_send_file(target)` branch. Two triggers: (a) `GovernedRun` construction raises (e.g. `RunManifest.open` on a damaged `committed.json` — precisely the moment fail-closed exists for) → `_refused` window → 2 seconds of static baked serving, renewed on every retry while the damage lasts; (b) a *transient* `OSError`/`ValueError` reading the picture's `zarr.json` in `_what_it_was_built_from` → `_the_serving_behind(store, None)` returns `None` → `_composers[store] = None` is cached **permanently** as "ordinary image" → static baked serving until `forget()`. On this site's machines (endpoint protection holding fresh files) (b) is not theoretical. Cure: distinguish "read and found not-built" from "could not read"; for a store whose classification failed, `a_manifest_governs` must fail closed (treat as governed / answer absent), and the permanent `None` must only be cached after a successful read.

**D4 — The backend's governed-route check is bypassable by path aliasing. MEDIUM (adversarial/buggy client only), high confidence.**
`server.py _a_piece_of_a_governed_picture` parses the raw `rel` string (exactly 5 parts, `parts[1] == "c"`, decimals), while `library.resolve` builds `(root / rest).resolve()`, which collapses `//`, `.` and internal `..`. So `/data/0/store/0/c//0/0/0`, `0/./c/0/0/0`, or `0/c/0/0/../0/0` resolves to the real baked chunk, fails the strict parse, and is served by `_send_file` — no derive, no patch, stale-past-manifest bytes on demand. The engine never asks such paths, but the gate's own words don't grant that exemption. Cure: canonicalize before the check (derive the piece address from the resolved target relative to the resolved store), or intercept by resolved-target membership in a governed store.

**D5 — Re-declaring under a running server serves declare-time baked files stale forever. MEDIUM-HIGH, high confidence.**
`served.py _composers` caches the `GovernedRun` per path with no invalidation on the store's `zarr.json` changing; `governed.py _the_baked_levels` caches `_baked` once. Its docstring claims "re-declaring … is served by a fresh GovernedRun" — nothing creates one. Toggle unbaked→baked while the server is up: cached `_baked=()` means `composer()` never patches, but `the_bytes_behind`'s `baked.is_file()` now finds the new declare-time files and serves them, going stale with every commit. Cure: key the `_composers` entry (or `_baked`) on the picture `zarr.json` identity, as `server._described` already does.

**D6 — Catch-up and in-session dirtying are blind to geometry (layout-revision) change. MEDIUM (conditional on mid-run revisions), high confidence in consequence.**
`governed.py`: `_the_ground_the_bake_missed` computes missed footprints from the **current** snapshot only — ground a missed event covered under an older layout revision (moved or no-longer-placed position) is never repatched; `_what_changed_dirtied` keys on generation deltas only, so a layout revision with no generation change dirties *nothing* while `TheWorldFrame`'s min-origin and shape can move (one more-negative placement added → every `lands_at` shifts → every baked piece and every inherited cache silently wrong). `_geometry` deliberately supports loading new revisions mid-run, so the path exists. Cure: a derive that observes a different `(layout.revision, profile_id)` from the held snapshot must dirty everything (bake and inherited caches); the stamp should record the revision it baked under.

**D7 — Multi-instance patching is unguarded (Q3's inter-process half).** `governed.py _replace_one_piece` / `_rehalve_one_level`: shared sidecar names and shared staging dir across `GovernedRun` instances in different processes; no file lock. Operational discipline is the only guard. MEDIUM-LOW.

**D8 — The catch-up path reintroduces a second manifest reader.** `_the_ground_the_bake_missed` calls `self._run.manifest.events()` directly — the exact racing-reader the addendum says was cured by stamping the fold's own count. Bounded to first-derive-of-session; failure mode is a refused derive (fail-closed) or over-patch, not wrong bytes. LOW, but it contradicts the recorded cure.

**D9 — Missing/torn stamp is a synchronous full re-bake inside the first request.** `_keep_the_bake_true` with everything dirty rebuilds every pinned piece and rehalves every extended level before any request is answered — the ~80 s-class cost at 12,769, blocking all requests behind `_bake_guard`. `stamp_the_bake` writes `baked.json` via non-atomic `write_text`, so a crash mid-stamp manufactures this cliff. Honest, but the cliff should at least be an atomic replace away from being rare. LOW-MEDIUM.

**D10 — Older-snapshot install race.** `composer()`'s install condition `mark != self._mark` lets a thread holding the *older* fingerprint replace a newer held snapshot (the comment "two threads may have derived the same snapshot" understates: they may have derived different ones). Self-heals on the next ask; bake never regresses; the exposure is one request answered from the superseded state after the newer state was already served — the same order as the inherent fingerprint-then-fold TOCTOU, but the comment's claim is wrong and the window is avoidable (compare fold counts, install only forward). LOW.

Minor: `TheWorldFrame._origins` class dict never evicted; a crashed `.patching-{level}` dir can linger inside the store indefinitely.

## (3) Q6/Q7 and the cheapest writer win

**(a) Per-change validation over a remembered baseline is sound**, and consistent with the codebase's own precedent (`how_the_array_is_stored` remembers against file identity; `_LiveRun` folds incrementally; `_geometry` skips reloading a known revision). The decisive observation: the **deep** checks are already per-change — `_read_every_piece` and `_follow_the_stored_pointers` read only the published position's own pixels/pointers. What `route_the_view` re-does O(survey)-times is (i) mutual storage consistency, which is transitive through the `first` exemplar, so newcomer-vs-remembered-exemplar is *exactly* equivalent; (ii) per-position geometry arithmetic over immutable inputs (layout revision + a store description that the publication rules never rewrite); (iii) the `reaches` vs `view_shape` max, which a newcomer can only extend and which is maintainable incrementally. The only guarantee genuinely surrendered: noticing at publish time that a *settled* position's `zarr.json` was rewritten on disk — an invariant violation the memoized `how_the_array_is_stored` already only guards by stat identity; keep a one-stat-per-position sweep if that guard is wanted (cheap relative to 26 s).

**(b) What must invalidate the baseline** (all found in the code):
- `layout.revision` (placements, `_mosaic_extent` → `view_shape`, corner arithmetic; `_read_the_link_map` already refuses a mismatched revision);
- `profile.profile_id` (linkable_levels, downsampling, frame_shape, channels);
- any change to the committed set other than the single admitted change — i.e. **reopen/recovery**: `_committed_units` is re-derived from the manifest, and a history that came back shorter must reset the baseline exactly as the gateway resets its fold;
- a **generation bump** of any position (its array path changes; re-validate that entry, replace its block);
- the **failed-replacement rollback** (`_restore_shared_state_after_failed_replacement` rewrites the map from committed units — the candidate baseline must be discarded there);
- the **link-map file's on-disk identity** moving outside the rememberer's own last write (another process, hand edit) — remember the mark written, re-read on mismatch;
- **draw order**: `showing` order is commit order and is part of the meaning (`arrival` is load-bearing in `_Block`); anything that changes settled positions' indices (a rollback removing a middle position) invalidates every later block.

**(c) Sharing one routing.** Yes, with refusal kept separate. `write_the_link_map`'s route is the pre-write gate over the *candidate* (it includes the not-yet-committed position) and alone refuses before anything is written. `_follow_the_stored_pointers` and `_check_the_view_description` operate on the *stored* map and today build value-identical routes from **two separate reads of the same file** — they may share one read and one route per level with zero semantic change, provided a shared construction failure fails **both** `links_ready` and `view_ready` closed, and each keeps its own complaint list (the Inspection design's stated reason for separate lists). `inspect` may reuse `write_the_link_map`'s in-memory routes only if the file is proven byte-identical to what was written (read back, compare bytes); otherwise "the map on disk is what the server follows" silently becomes "the map in memory is", which is the drift `_follow_the_stored_pointers` exists to catch.

**(d) Cheapest semantics-preserving win.** The same state is routed 3× per level per publish from value-identical inputs. In order of increasing intrusion:
1. Merge the two stored-map consumers: one `_read_the_link_map` + one `route_the_view` per level shared by `_follow_the_stored_pointers` and `_check_the_view_description` — 12→8 calls, and one JSON parse of a 12,769-position map instead of two, with *literally the same checks executed*.
2. `write_the_link_map` returns its per-level routes and the exact JSON it wrote; `inspect` re-reads the file, byte-compares, and on equality reuses the routes — 8→4 calls; the round-trip guarantee is preserved by the byte compare (O(file), not O(route)).
Steps 1–2 alone should cut the ~26 s to roughly a third with unchanged guarantees; per-change baseline validation (Q6 proper) then removes the last sweep.
3. Same disease, smaller: `_committed_units` and `_positions_in_commit_order` (coordinator.py:353, 368) rescan the whole events cache per call, several calls per publish — fold incrementally as the gateway already does.

## (4) Numbers and claims vs code

**O(change) claim:** true of bytes touched — `dirtied` is footprint-based, pieces rebuilt individually, the extended tail shrinks geometrically. **Hidden O(survey) terms remain in every patch (derive):** `_compose_the_snapshot` rebuilds `drawing`/`tiles`/`ordered` over all positions; `Composer` + `TheWorldFrame` construction is O(positions) per derive; `TheWorldFrame.shape()` re-sweeps *all placements per level per derive* (only the origin is memoized across derives — `_shape` dies with each snapshot); `_what_changed_dirtied` iterates every tile of both composers to filter the changed ones; `inherit_the_unchanged` walks the donor's entire block/slab caches. All in-memory — tens of ms at 12,769 — but linear, and it will surface inside landing-to-visible latency at the 115,200 rung. Also: "baked cold open 0.3 s" and the same document's "cold derive 1.13 s" at the same rung cannot both describe the first answer's path (the first baked answer sits behind a derive); one was measured under different cache conditions.

**Claims the code contradicts:**
- "one reader per derive" — the catch-up path reads the manifest a second time (D8).
- "the stamp is the idempotence … never regresses" — the forward-only property is exactly what breaks under rollback (D1).
- "governed stores consult the run before any file door — including the backend's" — only for canonical piece paths (D4) and only while classification succeeds (D3, D5).
- Addendum "the plan above was implemented" — §3's generation-swap inheritance (Q4) has no code anywhere.
- `_the_baked_levels` docstring: "re-declaring … is served by a fresh GovernedRun" — nothing creates one (D5).
- The test file's stated central contract ("after an arbitrary churn — landings, replacements, **a rollback** …") — `test_a_governed_picture_is_baked_per_commit.py` covers landing, replacement, switch-off, WinError 5, and the HTTP door, but contains **no rollback/truncation case and no layout-revision case**; the two untested legs are precisely where D1 and D6 live.
