## What the operator sees

- **Orange on the rail.** A step that was settled once and not confirmed since something above it
  changed. Redoing a step -- editing a setting or running it again -- makes it green and every done
  step after it orange. Clicking around the rail never changes a colour. An interrupted step is
  orange too: it did part of its work.
- **Confirm settings** at the top of an orange step's box. Running the step again also confirms it.
- **Step 10, Run protocol.** Its box holds "Accept all current settings" and the press "Run
  protocol", greyed with the names of the steps still to confirm. The run walks the focus map (only when none is measured on this sample yet), scan
  (the whole plan), detection, the gates re-applied to the new objects, scan areas, targets. The
  rail and the step box follow it; the canvas stays the operator's; one Interrupt press, shown in
  whichever box the run stands in, ends the walk after the step in hand. Finishing writes
  `protocol.json` into the run folder.
- **Protocol box** under the Connect box, after connecting: *New protocol* or *Existing protocol*
  with the list of runs on this machine (newest first). Choosing one fills every step's settings:
  Connect green, 2-10 orange. The carrier is re-snapped on this sample, the rest confirmed or run.
- **Test tiles, Step 5.** Tiles pressed green on the picture, or "Select N random" (systematic
  uniform random sampling along the Z-curve). The scan takes only the green tiles while any are
  green; steps 6-9 work on what was scanned. Run protocol takes the whole plan. A plan redrawn
  clears them; an existing protocol brings last time's.
- **Complex feature dimensions** (PCA / UMAP) greyed out, "not available yet": a gate on those
  axes cannot be reapplied on the next sample.

## How it is built

- `framework/rules/steps.js`: `editedAt(steps, done, stale, id)` and `staleSteps(...)`, pure,
  tested in `steps.test.js`.
- `framework/window/main.js`: `state.stale` beside `state.done`; `stateEdited(id)` is the one
  hook (carrier shape/anchors/drag/keyboard, scan fields and their preset, focus preset and every
  focus-point edit through `focus-map.js`'s `edited`, detection settings through `detection.js`'s
  `edited`, gate commit, placing levers, target focus toggle, recording slots by `STEP_OF_SLOT`,
  test tiles); `confirmStep(id)`; `runStep` returns `{ outcome: finished | stopped | failed }`;
  `runProtocol()` / `interruptProtocol()` / `protocolMount()`; `state.scanned = { plan, fields }`
  is what every result is read through (`scannedPlan()`, and `fieldsOf(run)` in the layers), so a
  picture stays where it was taken when the plan is edited; the old `scanfieldsLocked` /
  `focusLocked` / `carrierLocked` are gone. Detection keeps the gates and re-derives `gated` when
  it finishes. `chooseProtocol(id)` applies a listed protocol.
- `framework/window/protocol.js`: `protocolFrom(state)`, `applyProtocol(state, json)`,
  `protocolFits(state, json)`; `protocol.test.js` goes through a real file.
- `workflows/target_acquisition/steps/run_protocol/step.js`: the tenth step; `the-run.js` lists it.
- Bridge: `GET /api/protocols` (under the connected session's output root, settings inline),
  `POST /api/protocol`; tests at the end of `framework/test_operator_bridge.py`. Backends:
  `live.js` and `mock.js` `protocols()` / `saveProtocol()`.
- `steps/connect/session-card.js`: the Protocol box. `steps/scan_the_overview/layers.js`: the
  `testTiles` layer (outlines above the pictures); `shared/stage.js`: tile press on the scan step.
- `walk.spec.js` walks all ten steps: three test tiles, the orange/confirm/accept flow, Run
  protocol over the whole plan, the protocol written, reconnect on it with 2-10 orange.
